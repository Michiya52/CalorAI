identifyFoodFromImage() method sends image bytes to Gemini 3.5 Flash along with a detailed five-step prompt, with automatic fallback to Gemini 3.0 and then Gemini 2.5 Flash if the primary model is unavailable or rate-limited. Unlike a simple classification request, the prompt is structured to make the model reason explicitly: Step 1 asks it to inventory visible features (broth colour, protein type, noodle or rice base, toppings, cooking style, serving vessel). Step 2 gives the model named visual differentiators between commonly confused dishes, for example distinguishing Curry Mee's coconut-based broth from Laksa Lemak's thicker coconut curry, or KL-style Hokkien Mee's dark braised noodles from Penang-style Hokkien Mee's prawn soup. Step 3 governs ranking and honesty about uncertainty. Step 4 governs portion estimation using typical Malaysian serving sizes as reference points. Step 5 defines the strict JSON output schema. Critically, the model is asked to estimate the full nutritional profile itself — calories, protein, carbs, fats, sodium, and sugar — for each candidate, not just identify the dish name. The excerpt below shows the prompt's structure; the full prompt in the codebase runs to several hundred lines including a reference list of over a dozen commonly confused Malaysian and regional dishes.                gemini_service.dart — identifyFoodFromImage() prompt (excerpted)                       final prompt = '''             You are a world-class Malaysian and Southeast Asian food identification             expert with deep knowledge of regional cuisine variations.                Identify the main visible dish and return the 4 most likely guesses,             ranked from most likely to least likely, based only on visible evidence.                STEP 1 - VISUAL FEATURE ANALYSIS             - Broth/sauce: color, opacity, thickness, oiliness             - Protein: visible type, amount, preparation style             - Base: noodle type (yellow mee, kuey teow, mihun...) or rice type             - Toppings: bean sprouts, sambal, fried shallots, cockles, herbs...             - Cooking style: soupy, dry, stir-fried, grilled, braised                STEP 2 - DISTINGUISH SIMILAR DISHES             - Curry Mee: creamy orange coconut broth, tofu puffs, cockles             - Laksa Lemak: thicker coconut curry broth, shredded chicken/prawn             - Asam Laksa: dark sour tamarind broth, mackerel flakes, no coconut             - Hokkien Mee (KL): dark soy-braised thick noodles             - Hokkien Mee (Penang): prawn-based soup, clearer reddish broth               [... full list covers 16 commonly confused dish pairs ...]                STEP 3 - UNCERTAINTY AND RANKING             - Rank by actual visual likelihood, not popularity             - Reduce confidence realistically if image is blurry or ambiguous                STEP 4 - PORTION ESTIMATION             - Soups: ~400-500g | Dry noodle/rice dishes: ~250-350g                STEP 5 - OUTPUT FORMAT (JSON array of exactly 4 objects)             [{               "rank": 1, "dishNameEn": "", "dishNameMy": "",               "mainIngredients": [], "estimatedPortionGrams": 0,               "estimatedCalories": 0, "estimatedProteinG": 0,               "estimatedCarbsG": 0, "estimatedFatsG": 0,               "estimatedSodiumG": 0, "estimatedSugarG": 0,               "confidence": "high|medium|low", "confidencePercent": 0,               "cookingMethod": "", "visualEvidence": ""             }]                CRITICAL RULES: Return ONLY the JSON array. No markdown. Exactly 4             objects. confidencePercent 80-99 only with strong visible evidence,             50-79 if likely but uncertain, 1-49 if ambiguous or low quality.             ''';                 Figure 23: gemini_service.dart — identifyFoodFromImage() prompt structure (abridged from the full prompt in code)                  4.8.2 OpenRouter Chatbot — openrouter_service.dart              OpenRouterService builds a considerably richer system prompt than a single day's snapshot. Beyond today's progress (calories, protein, carbs, and fats consumed versus target, with remaining budget), it injects a 7-day weekly overview covering average daily         intake, the user's most-eaten foods, and total meals logged that week, followed by a short recent meal log. The prompt then lays out explicit sections for core behavior, accuracy rules (favouring realistic ranges over false precision, asking one clarifying question when a calorie-critical detail like oil or portion size is missing), Malaysian-specific food estimation guidance, response style (under 200 words by default, no markdown headers, mobile-friendly formatting), progress awareness, and safety guidelines that explicitly prohibit diagnosing medical conditions and redirect health-specific questions to a doctor or registered dietitian. A conversationMemory field is appended at the end when prior context exists. The response streams back over SSE so the UI renders chunks as they arrive.                openrouter_service.dart — buildSystemPrompt() (excerpted)                      return '''             You are CalorAI, a friendly, knowledgeable, and practical Malaysian             nutrition assistant.                === USER PROFILE ===             Name: \${profile.name} | Goal: \${profile.goal}             Daily calorie target: \${profile.calorieTarget} kcal             Age: \${profile.age} | Sex: \${profile.sex} | BMI: \${bmi} (\$bmiCategory)                === TODAY'S PROGRESS ===             Calories: \$todayCalories / \${profile.calorieTarget} kcal (\$remaining remaining)             Protein: \${todayProtein}g / \${macroTargets.proteinG}g - \$proteinNote                === WEEKLY OVERVIEW (7 days) ===             Average daily intake: \$avgDailyCalories kcal             Most eaten foods: \$top3             Total meals this week: \${recentMeals.length}                === RECENT MEALS ===             \$mealLog                === ACCURACY RULES ===             - Never present estimates as exact facts; prefer realistic ranges.             - Ask ONE brief clarifying question if a calorie-critical detail               (oil, sugar, portion size) is missing and materially changes it.             - For hawker/restaurant food, account for hidden oil, sauces,               coconut milk, and frying.                === RESPONSE STYLE ===             - Warm, concise, under 200 words by default.             - Simple markdown only (**bold**, '- ' bullets). No headers (#).                === SAFETY GUIDELINES ===             - Do not diagnose medical conditions.              - Redirect medical/disease-specific questions to a doctor or               registered dietitian; give only general wellness guidance.                \${conversationMemory.isNotEmpty ? conversationMemory : ''}             ''';                 Figure 24: openrouter_service.dart — buildSystemPrompt() structure (abridged from the full prompt in code)                  4.8.3 Calorie Calculator — calorie_calculator.dart              The calculator applies the Mifflin-St Jeor BMR formula, multiplies by the activity factor, then applies the goal offset.                      class CalorieCalculator {             /// BMR in kcal/day using the Mifflin-St Jeor formula             static double calculateBMR({               required double weightKg,               required double heightCm,               required int age,               required String sex, // 'male' | 'female'             }) {               if (sex == 'male') {                 return (10 * weightKg) + (6.25 * heightCm) - (5 * age) + 5;               } else {                 return (10 * weightKg) + (6.25 * heightCm) - (5 * age) - 161;               }             }                      static const Map&lt;String, double&gt; activityMultipliers = {               'sedentary': 1.2,               'lightly_active': 1.375,               'moderately_active': 1.55,               'very_active': 1.725,             };                      static const Map&lt;String, int&gt; goalAdjustments = {               'lose_weight': -500,               'maintain': 0,               'gain_muscle': 300,               'eat_healthier': 0,             };                      /// Recommended daily kcal target             static int calculateTarget({               required double weightKg,               required double heightCm,               required int age,               required String sex,               required String activityLevel,               required String goal,             }) {               final bmr = calculateBMR(                 weightKg: weightKg,                 heightCm: heightCm,                 age: age,                 sex: sex,                        );               final tdee = bmr * (activityMultipliers[activityLevel] ?? 1.2);               final adjustment = goalAdjustments[goal] ?? 0;               return (tdee + adjustment).round();             }           }                 Figure 25: calorie_calculator.dart — calculate()                  4.9 Summary              Chapter 4 has covered the full design and implementation of CalorAI.
