Validation errors appear inline below the relevant field. The Forgot Password link sits below the Login button and does not interrupt the main flow.                   4.6.2 Profile Setup Screen                                                                                                                                                      Figure 13: Profile Setup Screen                Profile setup is implemented as a single screen (profile_setup_screen.dart) with three internal steps tracked by a _currentStep index rather than three separate routed screens. Step 1 collects name, sex, age, height, and weight. Step 2 collects the health goal and activity level. Step 3 shows the calculated daily calorie and macro targets, with the option to override either manually before finishing.                                4.6.3 Home Dashboard Screen                                                                      Figure 14: Home Dashboard Screen                The calorie ring fills as consumed calories approach the target and changes color when the budget is exceeded. Macro bars show grams consumed rather than percentages, which is more useful for users tracking protein for a specific fitness goal. The meal list below is ordered by timestamp and shows the source label for each entry.                                     4.6.4 Photo Logging — Camera and Suggestion Cards                                                                                                              Figure 15: Photo Logging Screen (left, route /log/photo) and Suggestion Cards Screen (right, route /log/suggestions)                Photo capture and suggestion display are implemented as two separate routed screens (photo_logging_screen.dart at /log/photo and a dedicated suggestion_cards_screen.dart at /log/suggestions), rather than two states within a single screen. After capture, the four suggestion cards are shown via a shared suggestion_card.dart widget, each rendering a ConfidenceBadge (driven by the suggestion's effectiveConfidencePercent value), a source tag indicating whether MyFCD or SG Focos data was applied, a caloric density         indicator (Low, Med, or High, based on kcal per gram), and estimated calories for the default medium portion. The same ConfidenceBadge and percentage text ("AI confidence: X%") reappear on the Portion Selection screen once a card is chosen, so the confidence signal is not lost after the initial selection. If none of the four are correct, a 'Search manually' option is available at the bottom.                                4.6.5 Portion Selection Screen                                                                      Figure 16: Portion Selection Screen                Three preset buttons (Small, Medium, Large) show pre-calculated values from the food's portionSizes data. A portion multiplier slider (0.5x to 2.0x) lets users fine-tune without committing to a fixed size. All values update live as the slider moves.                                4.6.6 Barcode Scanner Screen                                                                      Figure 17: Barcode Scanner Screen                The scanner shows a targeting frame over the live camera feed. On barcode detection the app extracts the GTIN and transitions immediately to product display. If not found, a not-found message appears with a direct link to manual search.                                4.6.7 Manual Food Search Screen                                                                      Figure 18: Manual Food Search Screen                A SegmentedButton at the top switches between the regional sources (MyFCD + SG Focos) and USDA. The field uses debounced input, triggering a query 400ms after the user stops typing. Results show the food name, group, calories per 100g, and source badge.                                4.6.8 Composite Meal Builder Screen                                                                      Figure 19: Composite Meal Builder Screen                The running totals header updates each time an ingredient is added or its gram weight changed. Ingredients are removable by swiping. When the user taps Log, the composite entry is saved with the full ingredient breakdown nested inside the MealEntry document.                                4.6.9 Chatbot Screen                                                                      Figure 20: Chatbot Screen                The chatbot opens as a full screen to avoid z-index conflicts with the navigation bar (resolved via showModalBottomSheet with useRootNavigator: true in earlier iterations; the current implementation uses a dedicated route). Quick-prompt chips at the top cover the most common requests. Responses render in chunks as they stream from OpenRouter, formatted with flutter_markdown so bold text and bullet lists in the model's reply render properly rather than showing raw markdown syntax. Because the system prompt injects a 7-day weekly overview alongside today's progress, the chatbot can reference patterns like average daily intake or frequently logged foods, not just the current day.                                4.6.10 Meal History and Meal Detail Screens                                                                                                              Figure 21: Meal History Screen (left) and Meal Detail Screen (right, route /meal-detail)                Meal history groups entries by date in a collapsible format. Tapping any entry opens MealDetailScreen, which shows the full nutritional breakdown, the source label, the confidence and density badges where applicable, and for composite entries, the individual ingredient list built via the Meal Creator flow. Weight is currently captured only as a single static field on the user's profile (updated through the profile screen), not as a historical log with its own screen. The WeightLog model and the corresponding Firestore weight_logs collection and security rules already exist in the codebase, but no screen currently reads from or writes to that collection. This gap is discussed further as a limitation in Chapter 5 and as a recommendation in Chapter 6.                   4.6.11 Profile Screen                                                                                                              Figure 22: Profile Screen                The profile screen shows current metrics and calorie target. Editing and saving any field updates Firestore and triggers a recalculation if auto-calculate is active. The theme toggle (light/dark/system) is accessible from this screen via ThemeProvider.
